| Term | English | Description |
|:-----|:-------|:-----|
| Element | Element | Deliverable or process. |
| Deliverable | Deliverable | Deliverables such as documents and programs. Also includes intangible things like mental understanding. Represented by rectangles. |
| Process | Process | Something that takes deliverables as input and produces deliverables as output. Represented by ovals. A process is either an atomic process or a composite process. |
| Atomic deliverable | Atomic deliverable | A deliverable that is not decomposed further. The rectangle border is a single line or there is no border. |
| Composite deliverable | Composite deliverable | A set of deliverables. The rectangle border is a double line. Its breakdown is expressed in the composite deliverable table, and composite deliverables can be nested in multiple levels by listing another composite deliverable in the breakdown. In that case, the set of atomic deliverables that the composite deliverable represents is the set of atomic deliverables obtained by recursively expanding the contained composite deliverables. However, a cycle in which a composite deliverable transitively contains itself is not allowed. An edge connected to a composite deliverable has the same meaning as edges connected to each atomic deliverable in its breakdown. |
| Atomic process | Atomic process | The smallest unit of work that cannot be decomposed further. The oval border is a single line or there is no border. |
| Composite process | Composite process | A collection of atomic processes. The oval border is a double line. Composite processes can be nested in multiple levels by drawing another composite process on a detail page; in that case, the set of atomic processes that the composite process represents is the set of atomic processes obtained by recursively expanding the contained composite processes. However, a cycle in which a composite process transitively contains itself is not allowed. |
| Context diagram | Context diagram | A PFD where the entire process is treated as a composite process. That is, initial deliverables, final deliverables, and only one composite process are arranged. |
| Edge | Edge | A solid arrow connecting deliverables to processes or processes to deliverables. An edge from a deliverable to a process means that the deliverable is used by the process. An edge from a process to a deliverable means that the process creates the deliverable. |
| Feedback edge | Feedback edge | A dashed arrow connecting a deliverable to a process. The process at the end of the feedback edge can be executed multiple times; it cannot use the deliverable at the source of the feedback edge on the first run, but can use it from the second run onwards. |
| Feedback loop | Feedback loop | Among cycles that include feedback edges, those where the same element does not appear in the cycle. |
| Input deliverables | Input deliverables | Deliverables used by a process. Input deliverables do not include resources. For an atomic process, it is the deliverable that has an edge to that atomic process. For a composite process, it is the deliverable in the union of input deliverable sets of all atomic processes contained within, that is not created by any of the contained atomic processes. |
| Output deliverable | Output deliverable | A deliverable created by a process. For an atomic process, it is the deliverable that has an edge from that atomic process. For a composite process, it is the output deliverable of any of the contained atomic processes. |
| Initial deliverable | Initial deliverable | A deliverable in the PFD that is not created by any process. |
| Intermediate deliverable | Intermediate deliverable | A deliverable in the PFD that is neither an initial deliverable nor a final deliverable. |
| Final deliverables | Final deliverables | A deliverable in the PFD that is not used by any process. |
| Duplicate display | Duplicate display | Drawing one deliverable as multiple cells on the same page. Used to cut long edges short and make the diagram easier to read. All deliverable cells with the same ID refer to the same single deliverable. |
| Original | Original | Among the cells of a duplicate-displayed deliverable, the one cell that is not a duplicate. The cell that has the edge from the process that outputs the deliverable (the solid incoming edge) is the original. Duplicate cells are distinguished from the original by appending ＊ to the ID (`D10＊: foo`). |
| Element tables | Element tables | A set of process table, deliverable table, and composite process table. If the composite process table is empty, it may be omitted. |
| Deliverable table | Deliverable table | A table consisting of deliverable IDs and their descriptions. |
| Process table | Process table | A table consisting of process IDs and their descriptions. |
| Composite process table | Composite process table | A table of composite process IDs and their descriptions. Which processes a composite process contains is expressed not in this table but in its draw.io detail page (page name = composite process ID). The composite process consisting of the entire process set corresponding to the context diagram is obvious and therefore not listed. |
| Feasibility | Feasibility | If the scheduled worker can be confident that they can create output deliverables from input deliverables for a process, it is feasible. Otherwise, it is infeasible. |
| Execution Model | Execution Model | A model for defining process executability and calculating process execution plans from PFD. |
| Execution | Execution | The creation of output deliverables of a process. Processes are not always executable. |
| Time | Time | A floating-point number representing time in the execution model. Time 1 represents 1 business day, and the decimal part represents business hours within the business day with the decimal part rounded up. For example, with business hours of 09:00-18:00, time 1.5 represents 13:30 on the second business day. |
| Executability | Executability | The property of whether a process can be executed or not. The definition differs for each execution model. |
| Execution plan | Execution plan | A set of pairs of time intervals and processes. The pair means that the process is executed within the time interval. It can be represented by a Gantt chart. |
| Lead time | Lead time | The time it takes from starting a process to completing the output deliverable. |
| Resource | Resource | Something that can be used by any process and requires exclusive occupation during execution. For example, workers and equipment. |
| Available time of initial deliverables | Available time of initial deliverables | The time when initial deliverables become available. At times before this time, this deliverable is treated as non-existent. |
| Volume of work | Volume of work | The amount of work required from starting to completing an atomic process. |
| Remained volume of work | Remained volume of work | The amount of remaining work required until completion of an atomic process in the current state. |
| IDAP (Immediately done atomic process) | IDAP; Immediately done atomic process | An atomic process with a remaining work volume of 0. |
| IDAP set | IDAP set | A set of IDAPs that are completed in a certain state. The limit of the recurrence relation `f(n) = (if n = 0 then {ap. input deliverable set excluding feedback edges(ap) ⊆ deliverable set with revision updates in the immediately preceding state ∧ is IDAP(ap)} else {ap. input deliverable set excluding feedback edges(ap) ⊆ (⋃ (image output deliverable set (f(n))) ∪ deliverable set with revision updates in the immediately preceding state) ∧ is IDAP(ap)})` as `n→∞`. |
| Revision | Revision | The number of times a deliverable has been created or modified. 0 means the deliverable has not been created. |
| SM (Single deliverables execution model) | SM; Single deliverables execution model | An execution model where each deliverable is only one. The execution model is further divided by the finiteness of resources: FSM if resources are finite, ISM if infinite. |
| MM (Multiple deliverables execution model) | MM; Multiple deliverables execution model | An execution model where each deliverable can have multiple instances. Corresponds to Value Stream Mapping. Not handled in this project. |
| ISM (Infinite resources single deliverables execution model) | ISM; Infinite resources single deliverables execution model | A single deliverable execution model where resources are considered unlimited and there are no restrictions on available resources. Selected with `pfdplan -res infinite` (the default). It is implemented with the same state machine as FSM by using only allocation elements whose resource set is empty and whose consumed work volume is 1. The simplest model corresponding to PERT if there are no feedback edges. Being simple, it helps understand execution models. Also suitable for rough estimation since estimates can be made without interviewing process executors. However, since resources are finite in reality, it may generate execution plans that cannot actually be executed due to resource constraints. |
| Critical path | Critical path | See the definition of critical path in PERT. |
| FSM (Finite resources single deliverables execution model) | FSM; Finite resources single deliverables execution model | A single deliverable execution model where resources are finite and an atomic process can be executed if it can occupy the resources necessary for its execution. Selected with `pfdplan -res finite`. Can generate execution plans that reflect resource contention; the accuracy of the estimate still depends on the input estimates and the assumptions of the model. Not suitable for rough estimates as determining resources and consumed work volume requires cost and time for estimation. |
| FSM allocation | FSM allocation | A partial function from atomic processes to allocation elements. All allocations must satisfy the following conditions: (1) All atomic processes with defined allocation elements are executable, (2) For any distinct executable atomic processes ap1 and ap2, the resource set of ap1's allocation element and the resource set of ap2's allocation element are disjoint. |
| FSM allocation element | FSM allocation element | A pair of resource set and consumed work volume. In FSM the resource set is non-empty, while in ISM it is empty to represent that no resources are occupied. |
| FSM allocatability | FSM allocatability | Whether resources can be allocated to an atomic process if resources can be occupied. An atomic process is allocatable if it meets any of the following conditions: (1) Continuing execution, (2) The atomic process has all input deliverables generated, has at least one input deliverable that has been updated but not yet processed, has non-zero remaining work volume, and meets start conditions. Otherwise it is non-allocatable. |
| FSM executability | FSM executability | Whether an atomic process can be executed when resources are allocated to it. For atomic process ap, if all input deliverables have a revision of 1 or more and there are revision updates to input deliverables that have not yet been processed by ap, then ap is executable. Otherwise it is not executable. |
| FSM state | FSM state | A 7-tuple representing one execution situation in FSM: (1) time, (2) function from deliverable to revision, (3) function from atomic process to remaining work volume, (4) function from atomic process to its completion count, (5) function from atomic process to the number of times it has looped back to a feedback source deliverable starting from that atomic process, (6) function from each revision-updated deliverable to the set of atomic processes that take it as input and have not yet executed based on the updated revision, (7) allocation to continue execution. Execution state starts from one initial state, progresses through state transitions, and eventually reaches a completed state. |
| Initial state | Initial state | The initial execution state. Let A be the IDAP set when initial deliverables available at time 0 are treated as updated deliverables, and let D be the union of output deliverable sets of each element in A. The initial state satisfies: (1) time 0, (2) revisions of initial deliverables available at time 0 and elements of D are all 1, other revisions are 0, (3) remaining work volume of atomic processes is initial work volume, (4) completion count of atomic processes is 1 only for elements of A, 0 otherwise, (5) feedback loop count is 0 for all atomic processes, (6) for revision-updated deliverables being the union of deliverables available at time 0 and D, only atomic processes that take each as input and are not included in A have not processed the update, (7) allocation to continue execution is empty allocation. The initial state is uniquely determined for environments that satisfy invariant conditions. |
| Completed state | Completed state | A state where execution is completed. The current time is greater than or equal to the maximum available time of all deliverables, and there are no allocatable atomic processes. |
